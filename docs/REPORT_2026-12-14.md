## Results

- **Round 38's two FAILs are explained.**
  - **T1 (the robot's "readable" mode changes a save): no reader gives a wrong answer. It is the clock.**
    - On bt-castle-shop and bt-ch8-support, the saved Chapter0 differs in exactly one byte. That byte is the lowest byte of a saved time of day (the game's "real time played" clock).
    - Why: a readable piece answers in PC code and spends no game-processor time. So the next clock read in that frame comes about 1 thousandth of a second earlier. Here that crosses a millisecond, and the saved time is 1 lower.
    - Proven with a clock log: the same clock reads, in the same order, from the same callers. Only the values just before the save are 1 lower.
    - No single readable piece causes it. It needs many of them together, because the time adds up.
    - "Shadow" mode runs the readers and compares their answers, but lets the game keep the original results and time. In that mode every save was byte-identical to the original game, with 0 mismatches. The only memory differences were a few bytes of leftover stack (9 bytes on one route, 4 on another).
