## In plain words (ELI5)

Think of the game as a huge recipe book written in a language only the 3DS reads. We rewrite the
recipes into plain language, one at a time. A robot plays the game and checks that each rewritten
recipe gives exactly the same dish as the original.

Some recipes only get cooked in rare moments: a forge that needs an ore the castle never gave, a
skill that fires on a lucky roll, a child unit that needs a long support chain. Waiting for those in
normal play could take days of robot play. So, with your OK from the night of 2026-11-12, the robot
may now **cheat in its own test game**: it changes a few numbers in memory (one Pearl in the castle
stock, a skill's chance set to 100%) and then plays on. Three rules keep this honest:

1. **Only the robot's own copy.** Never your saves, your Zakuro cheat file or your mods folder.
2. **Labelled and counted apart.** Those pieces are called `cheat-...`, and their results go in a
   separate table. A recipe checked only there is reported as "checked on a cheat route", never as
   "checked in play".
3. **A cheat save never starts a normal piece.** The robot refuses it, even if the save is renamed
   or repacked. The last review found a way around this rule. It is fixed, and the fix was tested
   by trying the reviewer's trick again: refused.

Second, the **options screen**. Four of Grok's option ideas (danger zone, map HP bars, battle
animations, game speed) turn out to be switches the game already has. They live in one block of
settings, and that block is stored inside **every game save**. The code that reads these settings
