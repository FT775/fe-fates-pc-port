# Grok on the public release plan (2026-11-26)

Asked once by Claude after the desk plan docs/PUBLIC_RELEASE_PLAN.md was drafted (no game data, no private details
sent). The question: build/relplan/grok_relplan.txt. Grok's answer, word for word:

> Replace the public snapshot. Force-push a fresh one-commit tree. r68 has Seal-derived files in it, and a superseded release still lets people download them. Delete the r68 GitHub release, including its zip. The private repo keeps the history.
>
> Do the 10 hours. A stranger's first click is the release. Exit codes, four tests that fail in an unpacked zip, and a Read Me that says Road A is the plain game and Road B needs a compiler are the release. Do not add a clean-PC trial as a blocker. Do not add more features in front of it.
>
> Do not wait for a full seed. Wait for one fight, if you can do it before the public push. The notes should say you have not played a randomized game to the end. A source zip is not a finished game, and the Seal files should not stay public while you wait.
