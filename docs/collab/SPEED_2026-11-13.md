# Where the time goes: robot playthroughs and tests

**Note on Grok:** Grok was not contacted in this run. All three measurement steps were read-only, and none of them messaged Grok. Grok has also written nothing on robot speed so far: EFFICIENCY_GROK.md covers integrate time, and JOBS_GROK_6.md only mentions the in-game options. The questions to take to Grok are at the end.

## TLDR
- **The emulator is not the problem.** boot.exe has no frame cap and runs at about 450 to 580 fps (7 to 10x realtime). A full replay runs at 6.3x even with 12 runs going at once.
- **Model thinking is not the main problem either.** It was 15% of bt chapter 10, 26% of split, and 7.5% of the round-7 test critical path.
- **The real cost is the way the tools drive the game.**
  - Every 22 to 70 frames of play starts a fresh boot.exe and runs a full Python post-pass. Each step costs about 3.8 s, of which about 0.5 s is emulation, so about 85% of every step is overhead.
  - As a result a chapter advances at **0.28x realtime**. That is about 18x slower than replaying the same frames.
- **Tests are slow because work is repeated and run one after another.**
  - check_all ran a fast pass and then a slow pass that repeats every fast row, all one row at a time.
  - The same 15 routes were played live twice in one round, with identical memory hashes.
  - H6 re-mutated files that had not changed.
  - H5 ran 3 times.

### Worth doing next, with owner OK
- **Parallel check_all** (longest-first, separate output folder per row, below-normal priority). The slow run goes from 81 min to about 12 to 14 min at 8 lanes (model; the floor is the 683 s assets-full row). Shared output folders are a medium risk. Owner OK: y.
- **New chains only: set the game's own options through its Options screen** in the robot's save: battle animations off, game speed always fast, enemy-phase skip on. This is real play, and Awakening's robot did the same. Estimated 30 to 50% fewer frames per chapter. Keep one chain with animations on so the battle-picture code stays covered. Do the change at a chain start, because a menu visit moves the RNG. Owner OK: y, because it changes the game state.
- **Replay stored records offline** when only the capture library changed (H5 shows offline equals live), instead of a second 17-min live capture. Needs a rule for newly hooked functions. Owner OK: y.
- **Count the capture run as the second determinism copy** (its hash already matches) and start it together with the original replay. Saves about 690 s per chapter. This changes the meaning of "2 matching copies", so owner OK: y.

### Agent side (prompt and workflow only)
- Batch a whole player phase into one call that stops on the first unexpected screen.
- Read the board as text; open a screenshot only for forecasts or surprises (418 PNG reads measured).
- Read the forecast numbers from memory instead of fore.png.
- Write a small planner for routine moves, with the LLM deciding the fights.
- Gain: model share from 15 to 26% down to under 10% (estimate).

## Combined estimate
- **Chapter:** tools-only changes 2 to 5 take bt chapter 10 from about 125 min to about 50 to 65 min (estimate). With the server mode (8), about 30 to 40 min, and agent thinking becomes the main cost.
- **Test round:** changes 1, 6 and 7 plus offline capture and parallel check_all take the critical path from 280 min to about 100 to 120 min (estimate).

## What NOT to do
- **No memory pokes, RNG seeding or state edits in real-play chains.** Those belong only on the F-019 cheat track (`cheat-*`, scored apart). Changing options through the game's own Options screen is real play; poking the option bytes is not.
- **Never relax "0 mismatches".**
  - Every speed-up must keep absolute-frame inputs that replay from frame 0 byte for byte.
  - The final clean replay with 2 matching copies stays.
  - Using the capture run as a copy needs the owner's agreement first.
- **No engine or boot.exe builds without owner OK.** That covers the server mode, any render or audio skip, and the software rasterizer (it crashes after a save loads).
- **Do not switch animations off in every chain.** That loses coverage of the battle-picture code.
- **Do not change options or the menu path in the middle of a chain.** It moves the RNG and changes frame counts.
- **Do not raise FEF_ROBOT_JOBS or run parallel branches in a way that takes slots from live 12-run sessions.** Contention already drops replays to 163 to 184 fps.
- **Do not cache test results without full-input keys and a periodic --no-cache run.**
- **Do not skip live capture for routes or hook addresses that changed.**
- **Do not move routine steps to a cheaper model without owner OK.** Misread screens cost restarts, and Conquest chapter 6 already lost about 25 to 30 min to retries.
