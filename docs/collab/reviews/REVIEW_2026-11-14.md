# Review round 5 — the cheat fence and the menu readers

ELI5 / ETA: This is a read of the cheat fence and the new menu readers, checked against their notes. Nothing in those tools was edited.

Read on 2026-11-14 from the working tree. `tools/harness/cheats.py`, `headless.py` (`save_is_cheat`, `check_start_save`, `pack_save`), `docs/CHEATS.md`, `docs/DECISIONS.md` F-019, `src/readable/menu/`, and `docs/MENUS.md`. No game file opened.

## What matches

- A cheat save does not start a real-play route. `check_start_save` refuses it before the save is laid out. `parallel.py` refuses it when the job is made. `h4a` calls `headless.run`, so the same refusal applies there. `pack_save` will not give a cheat run a plain name, and it writes the mark.
- `harness.py report` skips a run whose `run.json` has `cheat` or `start_save_cheat`. `parallel.py` adds cheat rows in a separate table. That is F-019, and the earlier hole (a cheat save named by `--save` on a real route) is closed in this code.
- The menu overrides do not write guest memory. A search of `src/readable/menu/` found no store. The picture decision and the HP-bar decision are helpers. `Danger::Update` and `Add` are not overrides. That matches `docs/MENUS.md`.

No high or medium finding. A labelled cheat run does not become a real-play total.

## Findings

### 1. Low — a capture folder with no cheat flag is merged as real play

`default_report_runs` skips a run only when `run.json` says `cheat` or `start_save_cheat`. A folder it cannot read (no `run.json`, or a broken one) is merged with the real-play runs. A cheat capture that lost that file, or an old one written before the flag, would count.

The pipeline writes the flag. This is the same family as the hand-edit limit already in `docs/CHEATS.md`: the harness cannot see a save whose bytes were changed by hand. Do not treat a report that did not print a skip line as proof that every folder under `runs/` was real play.

### 2. Low — the options table names one picture check; the code has two

`docs/MENUS.md` section 5 says `animation_skip` is `IsDetailBattle`. `menu_show.c` `battle_picture_choice` uses `IsDetailSupport` when the sequence's flags bit 2 is set (a support or a dance), and `IsDetailBattle` otherwise. Section 3 of the same note has that split. A wiring that follows only the section 5 line would leave a support fight and a dance on the picture the game would have skipped.

The host test still skips an early give-up, as the growth test does. A green menu run does not prove that a reader asked for the right cache first. `docs/MENUS.md` section 6 says a nested give-up is a mismatch. That part is in the test. The early skip is not mentioned.

## Left as the notes already say

- Stripping the mark and changing one byte of a save is not detectable. The fingerprint only matches a zip that is still in the saves folders.
- `enemy_phase` has a byte. What it does to the map was not read. No menu reader implements it.
