# Review round 4 — growth readers and the new markers

ELI5 / ETA: This is a read of the new level-up code and the new robot markers, checked against their own notes. Nothing in those tools was edited.

Read on 2026-11-13 from the working tree. `src/readable/unit/growth_rates.c`, `growth_exp.c`, `growth_roll.c`, `growth.h`, `docs/GROWTH.md`, `tools/harness/markers.py`, `tools/harness/levelups.py`, and the host test `growth_diff.py`. No game file opened.

## What matches

- The 23 overrides are readers. The five helpers return what `Unit::LevelUp` would store. `growth_roll.c` does not write guest memory. A search of the three C files found no guest store. That is the F-017 rule, and it holds.
- `unit_level_up_preview` matches section 5 of `docs/GROWTH.md` on the points that matter: a rate of 0 or below draws no roll, a sure point and a hit roll set "something rose" even when the cap refuses the point, and the pass stops at four. The host test plants the bug that would clear that flag, so that one is caught.
- `GetDualExpDamage` is half of `GetExpDamage` when the amount is 2 or more, as section 4 says. `GainExp` is not treated as the applier. That correction is already in section 9.

No high or medium finding. Nothing here stores a stat or grants experience.

## Findings

### 1. Low — the host test cannot catch a wrong early give-up

`unit_dual_exp_damage` (`growth_exp.c`) asks for the level cache and gives up before it calls `GetExpDamage`. The game calls `GetExpDamage` first, and that function asks for the cache. `growth_diff.py` treats an early give-up as always safe and skips the comparison. A green run does not prove that this function asked for the right cache, or that it asked before the call.

The same skip covers every function that asks for a callee's cache first, not only this one. Do not read a 0-mismatch line as a proof of that order.

### 2. Low — the partner's defeat share is not a tested entry

`docs/GROWTH.md` says `GetDualExpDestroy` is a one-word fall into `GetExpDamage`. The registry row for `unit_exp_damage` says the host test covers that address. `growth_diff.py` has no case for it. The original code still runs, so the game is fine. Do not claim the readable body is proven for the partner's defeat share until that address is in the test.

### 3. Low — two units with the same person id collapse

`markers.py` `unit_levels` stores one row per person id. A second unit with that id overwrites the first. `levelups.py` then cannot see a level-up on the one that was overwritten. The current Birthright routes have one of each person, so this does not hide a level-up already recorded. It will, the first time a duplicate joins.

A missing ore key is not 0 ore. `castle_stock` leaves the key out when the castle pointer cannot be read. The robot's 0 ore is a real zero only if the key is present and the count is 0.

## Left as the notes already say

- The animated experience bar was not read. The skip path adds the amount at once. Do not treat them as proven the same.
- A unit that joins, leaves, or falls between two shots is not compared. A level that wraps from 255 to 0 is not a rise, so `levelups.py` would miss it. Neither is a current route.
