ELI5 / ETA: This is a read of the new castle tools and the rewritten battle rules, checked against their own notes. Nothing in those tools was edited.

Read on 2026-11-12 from the working tree, not from a commit. `docs/FORMULAS.md` and the `formula_*.c` files were still untracked. The other files named in the job were already in the tree. No game file was opened.

## What matches

- Castle append policy matches `docs/CASTLE.md`. Only `DiningData_CookTitle` and `DiningData_Dish` are `allow` in `config/tables/castle/sheets.csv`. `tools/castle/castle.py` refuses a new row on any other sheet, refuses a new row with no label where a label is required, and refuses a row that carries a list or a pointer (`castle.py` around the append block). `AcceShop` stays refused. A cook-title insert is tested to move the dish rows (`tools/castle/test_castle.py`).
- Stance, triangle, and vein writers are helpers. They return what the game would store. The overrides in `stance_gauge.c`, `vein_units.c`, and `vein_tricks.c` are readers. `SetDeploy` is not an override (`vein_effect.c` header). That matches the "waiting" lists in `docs/STANCES.md`, `docs/TRIANGLE.md`, and `docs/VEINS.md`.
- A disadvantaged unit loses its weapon-rank bonus only when the fight passes the bool as 0. `unit_attack` and `unit_hit` add that bonus only when the bool is set (`formula_unit.c`). The triangle helper sets that bool from `triangle >= 0` (`triangle_battle.c`). There is no per-turn vein flag in `vein_units.c`. Who may use a vein is one cached flag, plus the download rule when state bit 28 is set.

No high or medium finding. Nothing here would install an army the game drops, or store a gauge, or fire a vein.

## Findings

### 1. Low — the short formula lines drop a rule the code keeps

`docs/FORMULAS.md` section 8 says enemies get half the class crit. `formula_unit.c` (`unit_crit`) gives an enemy half its class crit only when state bit 5 is clear. Section 2 of the same note has that exception. Section 8 also writes damage as attack minus defense. Section 5 still has the follower half, dragonskin, and terrain.

The game is fine. The risk is the next rules page. If section 8 is copied into `docs/tracks/rules/RULES.md` as the whole rule, a unit with that bit set is documented wrong, and a forecast that uses the short damage line will not match the fight.

Do not copy section 8 as the rule. Copy section 2 and section 5, or put the bit-5 exception and the fight modifiers back into section 8 before anyone treats it as the formula.

### 2. Low — a new castle row assumes the header sits before the rows

`tools/castle/sheetlib.py` `insert_rows` writes the new count at the header's old offset, and the comment says the header is before the rows. It does not check. If a sheet's row block started at or before that header, the count would be written into the shifted bytes and the game would still see the old count, or a broken header.

The dining tests cover the real dining file, where a cook-title insert moves the dish rows and still reads back. A scan of every sheet file was started and did not finish, so this is not shown on a file we ship. No change unless a new sheet file has its rows first.
