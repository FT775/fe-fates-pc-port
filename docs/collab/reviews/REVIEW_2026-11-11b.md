## Findings

### 1. A map can install more units than the game will create — medium

`tools/maps/maplib.py`, the army-size check, about lines 801–812. `tools/mods/mapface.py`, about lines 173–175, stages the file whenever that check did not call it an error.

What breaks: the comment on the check says the game creates no unit once an army holds 50 (`Dispos::Data::GetUnit`). Two edits still go through:

- Turning a difficulty on for units already in the file. If that puts one group over 50, the message is a note, not an error, because the check only refuses when that same group gained a new row.
- Adding units in other groups so the whole army, across groups, is over 50. That message is a warning. Warnings do not stop the build.

The file is staged and installed. The chapter loads. The extra units are never created. The owner is not told to stop.

How to see it: export a map, turn Lunatic on for enough existing units in one group that the group exceeds 50, and install. Or add units in a second group until the player army exceeds 50. `build` should warn or note, and still stage the file.

Fix: if any army on any difficulty is over 50 after the edit, that is an error, whether or not a new row was added to that group. A warning is not enough. The per-group message can stay, but it must use the same rule the comment already states.

## Checked, not a finding

- The first review's high item (move the old file aside, then write the journal) is fixed. `install` writes the journal entry, including the backup path, and flushes it before the move (`tools/mods/mods.py`, about lines 1760–1768). A crash after the move and before the new file is in place is undone by `uninstall`: a pending entry with a backup and no new file is put back (about lines 1607–1646). An old backup with no journal entry is put back when nothing is in its place (about lines 1650–1661).
- A file changed after install is left in place, and the next install refuses until `uninstall --restore-backups`. The refusal names that command. That is the second item from the first review, closed.
- Same-size picture swaps are written in place and refused if the length would change (`tools/assets/bch.py` `inject`, about lines 335–350). A different size goes through `bchwrite.py`, which refuses a non-power-of-two side, a shared pixel block, and a pointer into the pixels. A face resize is off unless the mod asks for it (`tools/mods/mapface.py`, about line 261).
- `portrait.py` `import_dir` builds every file before it writes any (about lines 311–322). A crash while writing the destination folder can leave a mix of old and new files there. That folder is the one the command was given, not Zakuro's mod folder. The mod install path does not use it. Not the same gap as the journal.
- The tile index `x | y << 5` assumes a map is at most 32 wide (`maplib.py`, about lines 31 and 58). Map size cannot be edited (`map.csv` is refused, about lines 962–965). No retail width was read. Not a finding unless a file is wider than 32, and this code says none is.
