## The one problem found, now fixed

In real play the game used the readable "hit" and "attack" functions 143 times each. Every time
they gave the same number as the game and left memory the same. But in 214 of those calls they
took a different path to get there: the game asks one of its own helpers ("what kind of weapon is
this?") 3 more times than the readable code does, because the readable code works that answer out
by itself. The checker counts that as a difference, and we decided (F-018 in docs/DECISIONS.md)
that a function is only "clean" when there are no differences of any kind.

**Fixed the same day.** The readable code now asks the game's helper those three questions too, in
the same order as the game. Checked four ways:

- made-up cases: 34,500 cases against the game's own code, 0 differences, and the test now also
  counts how often the helper is asked; 31 of 31 planted bugs caught (one new: the old behaviour);
- the slower check on a fake game state (tier 2): 0 differences over all 56 functions;
- the robot replayed Chapter 2, Chapter 7, the Chapter 8 pair and the castle shop with every
  readable function watched: 2,966 checks over 47 functions, **0 differences of any kind**
  ("hit" 55 times, "attack" 55 times), and the game ended in exactly the same state as before;
- the quick set of automatic checks passes again (38 pass, 12 skipped slow ones; the slow set was
  not rerun after the fix).

So the goal "0 differences in real play" is **met** (on those four pieces; the other six were not
replayed after the fix). Your settings folders were listed before and after: nothing changed.
