## F-013 (2026-11-10): Thumb code is written as Thumb inside ARM sections
Lead (integration). `tools/gen_asm.py` writes the 221 Thumb functions and the Thumb bodies
of ARM->Thumb stubs in `.thumb` mode inside the preceding ARM function's section; only
ARM functions start sections. Each Thumb instruction stays text only when GNU as gives
back its exact bytes; Thumb symbols are untyped labels so the linker never changes a
byte. Thumb BL/BLX are symbolic (`bl NAME`), so they move with the code, and the link
uses `--use-blx` so ld keeps Thumb->ARM calls as BLX instead of adding stubs. The shift
test predicts the Thumb calls and fails on any raw Thumb branch that crosses an insertion
point. `config/raw_insns.txt` (addresses only) is tracked. The rebuild is byte-identical
and the M1 tests pass with this registry. Details: docs/CODE.md.

## F-019 (2026-11-13): The cheat track: the robot may poke its own test game, labelled and counted apart

**Decision.** The owner's OK (2026-11-12, night, in chat): the test robot may change values in its
own test game's memory during headless runs. Never the owner's saves, the owner's Zakuro cheat
file or the mods folder; only the robot's own runs below build/. Such routes are named `cheat-*`,
carry `"cheat": true` and declare every poke in config/harness/routes.json: the frame, an address
path through the config/readable layouts, the size, the value, the expected old value and the
reason. `tools/harness/cheats.py` applies them between boot.exe stages by patching the savestate's
FCRAM, with no engine change, and run.json records each poke.

**What counts as cheat.** A run is a cheat run when its route pokes or its start save is a cheat
save. A save is a cheat save when it is named `cheat-*`, carries the cheat mark (the member
`harness-cheat.json`, written by `pack_save` into every save packed from a cheat run, never
extracted for the game), or holds byte for byte the same save files as one in build/harness/saves.

**Rules.** (1) A cheat save never starts a real-play (`bt-*` or other non-cheat) route:
`headless.run`, `parallel.py` and `pack_save` refuse it, whether the save is named by the route or
by `--save`; `recapture.py synth` refuses cheat runs. (2) `parallel.py` lists cheat runs and
totals their capture records in a separate table; `harness.py h4a` refuses cheat routes. (3) A
reader met only on a cheat route is reported as "met on a cheat route", never as met in play, and
the plan's real-play totals count only `bt-*` routes. (4) Each cheat route must replay
byte-deterministically (determinism x2) with its markers met. (5) Limit: someone editing the bytes
of a save zip by hand cannot be told apart from real play; the rule covers the robot's own
pipeline (names, the mark, fingerprints, run.json). docs/CHEATS.md has the details;
`check_all` rows `cheats-selftest` and `cheat-routes` hold the mechanism and the route rules.

**Known gap (2026-11-14 integrate).** `harness.py headless --mode capture` on a cheat route writes
under build/harness/runs, and `harness.py report` merges every run there without a cheat filter
(robot round 6 review). Nothing is mixed in today (the cheat runs there are original mode, with no
summary.tsv); until it is fixed, cheat routes are scored only with `parallel.py runs --mode capture`.
**Closed 2026-11-13 (Claude):** `default_report_runs` now skips runs whose run.json has `cheat` or
`start_save_cheat`, so `harness.py report` counts real play only.

## F-021 (2026-11-13): Writers are gated and logged; none runs before robot H6 and the owner's OK

Lead (integration, round 7; the writers stage's code, docs/WRITERS.md). F-006 and F-017 ("writers
wait") are now code: `src/readable/core/fe_writer.h` and `writer.c`, with the first writer,
`config_write_options` (the game options block, GameConfigData +0x8/+0xC/+0xE/+0x16), in
`src/readable/menu/menu_config_writer.c`. Both are compiled into the capture library from round 7 on,
and both are **OFF**.

**What the gate guarantees** [high: host tests, source checks, the built library].
(1) A writer runs only when all three hold: its `armed` value in writer.c's table is 1, its name is
in `FE_WRITERS`, and `FE_READABLE=readable`. Every writer ships with `armed=0` and the table is
`const` in library builds; only host tests (`-DFE_WRITER_TESTS`) can arm one. In the round 7
library (`parallel.py build`, FRESH 16:12) the compiler removed the `FE_WRITERS` read altogether:
the string is not in the DLL, so nothing can switch a writer on there. (2) Shadow, capture and
original mode refuse every writer and count the refusal; writers have no 3dsrecomp marker, so
`FE_ENTRY`, shadow mode and `verify` never call one. (3) No report, registry status or file
switches anything: the switch reads only the source constant, `FE_WRITERS` and the mode. (4) Every
store, the writer's own and every store of a game function it calls through `fe_writer_call`, is
logged (address, size, old, new, writer, frame, session) **before** the byte changes; undo is exact
or nothing (a byte the game changed since gives `FE_WRITER_CONFLICT` and changes nothing); a store
that could not be undone is refused and the session rolls back; the log is bounded (8,192 entries).
(5) Nothing calls a writer today: no hook and no options page.

**What must pass before any one writer is switched on**, in this order, for that writer:
the host comparison against the game's code (`check_all` `writer-diff`, `writer-diff-long`: 0
mismatches, every planted bug caught), the gate's own test (`writer-gate`), **robot H6 on the
writer and its game callees**, a replay route that makes the same change through the game's own
screen, and then **the owner's OK in chat for that writer**. Only after that may `armed` become 1 (a
reviewed source edit) and the library or engine be rebuilt (F-004 again). A green row at any step
switches nothing on.

**Where H5/H6 stand (robot round 7, docs/harness/H56.md)** [high for the counts]. On kept game
records of all 15 real-play routes (17,818 records, 0 bad): H5, 100 of 110 overrides met; branches
of the overrides' own code 330/549 (60.1%), with every readable callee 1,214/2,564 (47.3%); the
offline verdict equals the live one on every record. H6 (planted bugs in the readable *readers*):
**865 of 1,822 caught (47.5%)**, cheat track apart 522/1,254 (41.6%). The Awakening gate is 90%, so
**the H6 condition is not met**, and there is no writer H6 on Fates at all yet (no
docs/tracks/HOOK_LIST.md, no writer probes, no `writer` kind in targets.csv). The writers stay off.
Host results for the first writer: `writer_diff.py` 0 mismatches in 600 and 3,000 cases, 25/25
planted bugs; `writer_gate_test.py` 244/244, 17/17 planted bugs.

**Save consequence (recorded so nobody forgets).** The options block is written into every game save
(GameUserData::Serialize, docs/MENUS.md) and into every suspend save through versus::Data
(docs/OPTIONS_WIRING.md section 1). A writer that sets it in memory therefore reaches the next save,
and an undo cannot reach a save already written. The wiring design (OPTIONS_WIRING.md, hooks W1/W2)
is built around this and is design only.
